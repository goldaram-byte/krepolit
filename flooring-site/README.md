# flooring-site

Next.js 15 (App Router, TypeScript) каталог-сайт дилера напольных покрытий.
Полное ТЗ — [`../SPEC.md`](../SPEC.md), правила для разработки — [`../CLAUDE.md`](../CLAUDE.md).

## Статус: Спринт 4 (админка и контент)

**Спринт 1 — каркас:**
- Next.js 15 + TypeScript (strict) + Tailwind CSS.
- Схема Prisma (`prisma/schema.prisma`) по модели данных из SPEC.md §3, клиент на driver-adapter (`@prisma/adapter-pg`), т.к. Prisma 7 больше не читает `DATABASE_URL` напрямую из схемы.
- Базовый layout (шапка, подвал), главная, «О компании», «Доставка и оплата», «Контакты», «Политика конфиденциальности», «Спасибо».
- Единый компонент формы лида (`src/components/forms/LeadForm.tsx`): маска телефона, чекбокс согласия на ОПД, honeypot-поле, ссылка на политику конфиденциальности.
- `POST /api/leads`: валидация (zod), rate limit по IP, запись лида в БД, уведомление в Telegram.
- Конфиги для деплоя на VPS без Docker: `deploy/nginx.conf`, `deploy/flooring-site.service` (systemd).

**Спринт 2 — каталог:**
- Импорт каталога (`scripts/import/`): CLI `npm run import -- --supplier=<id>`, парсеры YML (Яндекс-фид) и XLSX/CSV с настраиваемым маппингом колонок (`Supplier.columnMapping`), общая логика upsert (новый SKU → черновик, существующий → обновление, пропавший из фида → `stockStatus=нет`, не удаляется), скачивание и оптимизация фото в WebP (`sharp`), отчёт в Telegram.
- Расчёт цены с защитой от демпинга ниже РРЦ (`src/lib/pricing.ts`) — используется импортом и (в будущем) ручным переопределением в админке.
- Каталог `/catalog` и `/catalog/[category]`: фильтры (бренд, толщина, класс износостойкости, декор, водостойкость, тёплый пол, цена, наличие) как GET-форма — целиком в URL, без JS; сортировка; пагинация; `rel=canonical` на чистую категорию.
- Карточка товара `/product/[slug]`: SSG + ISR (ревалидация раз в час), цена за упаковку и за м² одновременно, полная таблица характеристик, похожие декоры, страница не даёт 404 при уходе товара «в нет в наличии» (SPEC.md §6).
- Калькулятор метража — переиспользуемый компонент (`src/components/calculator/AreaCalculator.tsx`) на странице `/calculator` (с поиском товара) и на карточке товара (уже с привязанным товаром); учитывает запас на подрезку (прямая укладка 5%, диагональ 10%, ёлка 15%) и позволяет отправить расчёт как заявку.
- Добавлены поля `Product.waterproof`/`Product.warmFloorCompatible` (были в фильтрах §5, но отсутствовали в модели данных §3).

**Спринт 3 — конверсия и SEO:**
- Заказ образцов как отдельная воронка: корзина образцов до 5 шт. в `localStorage` (`src/lib/sample-cart.ts`), кнопка «Заказать образец» на карточке товара, страница `/samples` (адрес доставки + контакты) → `POST /api/samples` создаёт `Lead` и `SampleOrder` вместе, отдельным сообщением в Telegram.
- `/pro` — страница для дизайнеров и бригад с формой регистрации партнёра. Добавлен `LeadType.partner` в схему (в SPEC.md §3 такого типа нет, но §5 явно требует «отдельный канал, не смешивать с розницей» — без своего типа это было бы фикцией).
- Яндекс.Метрика: счётчик подключается только если задан `NEXT_PUBLIC_YANDEX_METRIKA_ID` (реального счётчика ещё нет), цели по каждому целевому действию (`src/lib/metrika.ts`) — `reachGoal` вызывается при успешной отправке любой формы лида и заказа образцов.
- JSON-LD целиком: `Organization` (во всех страницах), `BreadcrumbList` (категория, товар), `Product`+`Offer` с `priceCurrency`/`availability` (товар), `FAQPage` на реальном видимом контенте (блок «Как мы работаем без шоурума» на главной, блок вопросов на `/delivery`) — без фиктивных вопросов без ответов на странице.
- `sitemap.xml`/`robots.txt` (нативные `app/sitemap.ts`/`app/robots.ts`), обработка пагинации и фильтров в `rel=canonical`: фильтры/сортировка сворачиваются на чистую категорию, пагинация (`?page=N`) канонизируется сама на себя — у страницы 2 другие товары, схлопывать её в страницу 1 было бы неправильно.
- `/feed/yandex.xml` — YML-фид собственного каталога для Яндекс.Директа, цены — всегда `ourPrice` (уже проверенные на РРЦ).

**Спринт 4 — админка и контент:**
- Модуль импорта переехал из `scripts/import/` в `src/lib/import/` — общая логика (`runImport`) переиспользуется и CLI-командой, и кнопкой в админке, а не дублируется.
- Логин админки на своей сессии в БД: пароли хешируются встроенным `crypto.scrypt` (без лишней зависимости), сессия — по хешу opaque-токена в httpOnly-cookie, попытки входа лимитированы по IP. Бутстрап первого админа — `npm run create-admin -- --login=... --password=...`.
- Админка (`/admin`, авторизация обязательна для всех страниц кроме `/admin/login`):
  - Дашборд: лиды за 7/30 дней по типам, товары с флагом «ниже РРЦ», результат последнего импорта (новая модель `ImportRun`).
  - Лиды: фильтр по типу/статусу, смена статуса и заметка прямо в списке.
  - Товары: поиск, публикация/снятие, ручное переопределение цены (`Product.priceOverridden` — при включении импорт больше не пересчитывает цену этого товара по наценке поставщика, но РРЦ-пол всё равно применяется и на ручном вводе), редактирование SEO-полей.
  - Поставщики: настройка фида (URL, формат, маппинг колонок, наценка) и кнопка «Запустить импорт сейчас».
  - Статьи: создание и редактирование (Markdown).
- Блог: `/blog` и `/blog/[slug]` — оглавление по `##`-заголовкам, перелинковка на каталог/калькулятор прямо в тексте, микроразметка `FAQPage` по конвенции «`### Вопрос?` → следующий абзац = ответ». Опубликовано 5 статей по темам SPEC.md §5 (различия кварцвинил/SPC/LVT, класс износостойкости, тёплый пол, замковый/клеевой монтаж, расчёт метража).
- Второй поставщик (CSV, другой бренд и категория — «Ламинат») импортирован и проверен на реальной БД рядом с первым (YML) — впервые протестирован путь XLSX/CSV, который в Спринте 2 был реализован, но не проверен на реальных данных.

Не реализовано: 1С-интеграция и остальное из SPEC.md §11 (сознательно вне MVP).

## Разработка

```bash
npm install
cp .env.example .env   # заполнить DATABASE_URL и TELEGRAM_*
npm run db:migrate     # применить схему к локальной Postgres
npm run dev
```

`npm run build` собирает продакшн-бандл; `npm run postinstall` (запускается автоматически после `npm install`) генерирует Prisma-клиент в `src/generated/prisma` — эта папка не коммитится.

Локальная PostgreSQL для разработки (пример для Ubuntu/Debian):

```bash
apt-get install -y postgresql-16
service postgresql start
su postgres -c "psql -c \"CREATE USER flooring WITH PASSWORD 'devpassword' CREATEDB;\""
su postgres -c "psql -c \"CREATE DATABASE flooring OWNER flooring;\""
```

## Импорт каталога поставщика

```bash
npm run import -- --supplier=<id> [--no-images]
```

`--no-images` пропускает скачивание фото (быстрее для тестового прогона). Поставщик должен
существовать в таблице `suppliers` с заполненными `feedUrl`, `feedType` (`yml`/`xlsx`/`csv`) и,
для XLSX/CSV, `columnMapping` (JSON, см. `src/lib/import/types.ts#ColumnMapping`) — то же самое
можно настроить и запустить кнопкой в `/admin/suppliers/<id>`, CLI и админка используют одну и ту
же логику (`src/lib/import/run-import.ts`).

Для локальной проверки есть два тестовых фида: YML на 320 товаров одного бренда
(`scripts/import/fixtures/sample-feed.yml`, поставщик YML-формата) и CSV на 26 товаров другого
бренда/категории (`scripts/import/fixtures/sample-feed-laminate.csv`, проверяет путь XLSX/CSV).
Формат, который понимает парсер: для YML — структура `<yml_catalog><shop><categories>`/`<offers>`,
характеристики через `<param name="...">`, распознаваемые имена параметров — в
`src/lib/import/param-mapping.ts`; для XLSX/CSV — плоские колонки по `columnMapping`.

Скачанные и оптимизированные (WebP, `sharp`) фото сохраняются в `storage/images/products/` —
эта папка вне `public/`, чтобы не пересоздаваться при каждом деплое. На проде и в dev она должна
быть доступна как `public/uploads`:

```bash
mkdir -p storage/images/products
ln -s ../storage/images public/uploads
```

## Админка

```bash
npm run create-admin -- --login=admin --password=<пароль>
npm run seed-articles   # 5 стартовых статей блога
```

Дальше `/admin/login` — сессия хранится в БД (`AdminSession`, TTL 30 дней), попытки входа
лимитированы по IP. Раздел `/admin` целиком закрыт от неавторизованных редиректом на логин.

## Переменные окружения

См. `.env.example`:
- `DATABASE_URL` — строка подключения к PostgreSQL.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — бот и чат для уведомлений о заявках.
- `NEXT_PUBLIC_YANDEX_METRIKA_ID` — счётчик Метрики; без него аналитика просто не подключается.
- `NEXT_PUBLIC_SITE_URL` — домен для абсолютных ссылок в sitemap.xml, robots.txt, YML-фиде и JSON-LD.

## Деплой

VPS, без Docker: `systemd`-юнит (`deploy/flooring-site.service`) запускает `next start` за `nginx` (`deploy/nginx.conf`), HTTPS — через `certbot`. Перед первым запуском:

```bash
npm ci
npm run build
npm run db:deploy   # prisma migrate deploy
```

Оба конфига в `deploy/` — шаблоны с `TODO`-плейсхолдерами (домен, пути, пользователь), их нужно подставить под конкретный VPS.
